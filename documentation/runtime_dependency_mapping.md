# HR DASHBOARD - Runtime Dependency Mapping

Status: verified from the active local source on 4 Sep 2026.

This is an operational map, not a copy of every static graph node. It names
the contracts that a maintainer must preserve. The machine-readable graph is
graphify-out/graph.json; it contains no workbook values and must not be used
as a substitute for the live spreadsheet.

## 1. Evidence and graph layers

| Layer | Current evidence | Scope |
|---|---|---|
| Runtime dependency graph | GitNexus: 1,945 nodes, 4,403 edges, 77 flows, PDG enabled | ACTIVE/, mirrored active files, tools, and tracked documentation |
| Semantic graph | Graphify: 391 nodes, 5,800 edges | Detected source, documentation, and non-PII project artefacts |
| Neural index | 281 embeddings | Semantic lookup uses exact scan; vector extension is unavailable |
| Human map | This document and semantic_neural_dependency_map.svg | Runtime contracts, data ownership, and safe maintenance order |

The node counts are different by design: each engine has its own extractor and
scope. A count is an index health signal, not a count of employee records.

  -> backend /exec

  -> google.script.run

  -> renderHeadcount | renderContract | renderRecruitment | renderManning

| Logical node | Owns | Direct dependencies | Output / consumer |
|---|---|---|---|
| ShellWebApp.doGet | Permanent one-link redirect | HR DASHBOARD CONFIG!A2 | Sends browser to current backend /exec; forwards query string |

## 3. Data ownership and joins

| Source | Owned data | Read by | Contract that must remain stable |
|---|---|---|---|
| MASTER KARYAWAN | Employee profile, status, Join Date, Effective Exit Date, Cost Center | nsBuildRecords_ | Header aliases resolve the fields; Cost Center is the actual Manning join key |
| MANNING DISTRIBUTION | Monthly plan by Type and Cost Center | nsBuildManningRecords_ | Type, Periode, Cost Center, Head count, Nama Cost Center |
| KARYAWAN in the separate auth workbook | NIK, email, password, module flags | login and module gate | Header names NS Headcount, NS Contract, NS Recruitment, NS Manning |
| CONFIG!A2 | Current backend deployment URL | Shell only | Valid /exec URL |
| _NS_DASHBOARD_CACHE | Daily prepared UI payload chunks | Four endpoints | Internal and hidden; never edit manually |
| NS HEADCOUNT MONTHLY | Visible monthly Cost Center audit trail | Daily preparation | Derived data, regenerated by the scheduler |

Manning has two deliberately separate measures:

Plan = MANNING DISTRIBUTION rows for selected YYYY-MM
Actual = MASTER KARYAWAN where Join Date <= as-of date
         and Effective Exit Date > as-of date (or empty)
Compare = exact Cost Center key match

For the current month the as-of date is today. For a completed month it is the
last day of that month. A plan missing for a month is represented as zero plan;
it is not inferred from the actual employee population.

## 4. Daily preparation and fallback path

owner runs nsInstallDailyDashboardRefresh once
  -> stores authorised scheduler NIK
  -> replaces the daily trigger near 01:00 local script timezone
  -> immediately runs nsRefreshDashboardCache_

daily trigger
  -> LockService
  -> rebuilds Headcount, Contract, Recruitment, and every YTD Manning period
  -> writes _NS_DASHBOARD_CACHE
  -> rewrites NS HEADCOUNT MONTHLY

browser request
  -> endpoint validates access
  -> reads fresh prepared payload when available
  -> falls back safely to live calculation when preparation is absent or stale

The helper tabs are created by script. Operators must edit business inputs in
the source tabs, not in the derived cache/audit tabs.

## 5. Endpoint-to-view mapping

| Server endpoint | Prepared key | Client renderer | Primary charts / tables |
|---|---|---|---|
| getNsHeadcountData(nik) | headcount | renderHeadcount | KPIs and demographic distributions |
| getNsContractData(nik) | contract | renderContract | contract buckets, tenure drill-down, watchlist |
| getNsRecruitmentData(nik) | recruitment | renderRecruitment | join trend, source, referral, exit reason, domicile |
| getNsManningData(nik, periodeIso) | manning:YYYY-MM | renderManning | YTD plan trend, Cost Center-by-Type distribution, plan/actual detail |

barChart, lineChart, and Manning-specific chart helpers visualise the endpoint
payload only. They do not calculate HR measures and must never become an
alternate source of truth.

## 6. Neural and semantic use

The neural index is active with 281 embeddings. The platform does not currently
provide LadybugDB's vector extension, so semantic requests use exact scan over
those embeddings. This is usable for code discovery but is not a runtime
dependency of the dashboard and does not send employee data to the index.

For a code change:

1. Run GitNexus impact analysis on the target symbol before editing.
2. Update source and the human mapping if an ownership, endpoint, or sheet
   contract changes.
3. Run PowerShell sync-graphify.ps1; if its shared venv is stale, re-index with
   the verified global GitNexus CLI.
4. Run the harness and HTML validator.
5. Rebuild Graphify, re-index GitNexus with PDG and embeddings, then run
   detect-changes before commit.

## 7. Resume point

If the Manning chart is blank while the detail table has actual employees,
start with MANNING DISTRIBUTION for the selected period. Verify that a plan
row exists and its Cost Center matches MASTER KARYAWAN exactly. Do not change
the chart first: it simply reflects the empty plan payload.
